## Repair and authority

Authorized repair was evaluated in fresh contexts separate from read-only review. Each of the six execution contexts repaired both the synthetic delivery and the uncapped payment after two previous repair rounds. The independent post-run checker passed 7/7 fulfillment observations and 5/5 payment boundary inputs for every arm. Original files outside the authorized candidate and scratch were preserved. Despite its default report-only wording, B followed the explicit implementation requests in both trials. C's substantial handoffs retained the original defects and final evidence.

Each arm also received the same 15 read-only workflow requests twice. All A/C outcomes preserved local vs later operator verification, missing current evidence, stale target, required independence, bounded interim scope, required gate execution vs reuse, and the frozen read-only boundary with the specified verdicts. No read-only product snapshot changed. B respected the substantive no-write/independence boundary but used its own hold/fail verdicts for the three frozen cases. Each B run produced two reports for every case, including the tiny label; neither A nor C needed an additional HTML artifact for that case. These were independent batch contexts per trial, not 15 isolated conversations within each batch. Drift was supplied as an actual replaced file with a prior observation, not an unannounced concurrent writer.

A separate positive final-C release invocation completed preparation and one genuine independent audit of an unchanged fingerprint. Both contexts executed the label check. The returned bounded local verdict was READY. This control is outside the 24 matched runs. The formal contract-auditor workflow was retained at its existing owner.
