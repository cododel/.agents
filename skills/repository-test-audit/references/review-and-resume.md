# Semantic Review, Batches And QA

Read each group's assertions, setup/hooks/fixtures, expected helpers, decisive doubles, SUT and
independent obligation. Shared family context is not the boundary of every method: state the actual
method guarantee and limitations. Do not grade a whole file from one selected test. Sound equivalent
cases may share concise reasoning; differing inputs/layers/error timing/oracles require exceptions
or child groups, with every case identity retained.

Use the shared testing procedure to name realistic failure, independent expectation, observable
result and actual failing boundary. Test source describes what would execute, not evidence it ran.
Source counterfactuals must say unexecuted. A wrong SQL predicate can retain all tokens; a fake can
always serialize uniqueness; an exception stub can be swallowed. Those call for specific strengthening,
not blanket deletion. A graph resolver/hash recomputation/fail-before-DDL guard may be valuable
without a DB. Seek cross-layer companions before inventing duplicate integrations.

Overlap requires matching guarantee, failure mode, cases, oracle and actual boundary. A unit refund
decision, durable DB rollback and UI feedback protect different seams. Consolidation or retirement
of a live guarantee needs a named surviving/replacement group and preserved unique cases; incomplete
overlap search must be explicit. An obsolete requirement instead needs cancellation evidence and no
dependent consumers or remaining obligations, not replacement protection. Actual deletion always
needs separate authorization. A second source check is useful for risky removal recommendations;
no voting or numeric score substitutes for evidence.

## Resume and authorized parallelism

Prioritize financial/access/destructive state, lifecycle/concurrency and affected integration risks;
risk orders work, never determines verdict. Batch size follows complexity/context, not a quota.
Retain task scope and source/test/helper/SUT/contract/config fingerprints separately from progress.
On resume/source drift refresh inventory, exact case memberships and dependent verdicts. Changed
shared dependencies invalidate affected groups/summary; verified independent results may transfer.
Statuses pending/in-review/reviewed/blocked/stale are separate from runtime outcomes.

Use parallel review when explicitly authorized or applicable instructions request it and independent
units make it useful. Bound active reviewers by available capacity. Coordinator owns frozen scope,
ledger and synthesis; each reviewer has exclusive group/case ownership, source identity, accessible
contracts/shared helpers and read-only boundaries. Do not prime verdicts or hide material context.
Shared helpers may be read by multiple reviewers; cross-domain conclusions return to coordinator.

Reviewers return IDs/memberships/fingerprints, evidence classes, verdict/actions/unknowns and overlap
references. Deduplicate second reviews by unique leaf IDs; count a case once. Resolve conflicting
claims from sources, not majority agreement. Reassign stale/incomplete-context reviews. Domain/global
judgments derive from verified records and denominators, not automated routing categories.

## Mechanical and semantic QA

Mechanical QA checks identities/counts/mappings/hashes/mandatory fields/reference existence and
precision; it cannot validate rationale truth. Line-specific evidence is preferable for decisive
assertions/SUT; file-only references stay explicitly coarser. Resolve all referenced paths correctly.

Semantic QA samples risky candidates and broad claims against actual test/helper/SUT source. Repeated
oracle/family prose is a lead to inspect, not proof of either invalidity or authored review. Ensure
method-specific boundary, verdict/action consistency and applicable live-protection or
cancellation/consumer evidence. A strengthen verdict
with only "preserve" needs a concrete improvement/evidence action; conditional consolidation without
replacement proof becomes investigate with the exact next evidence.
