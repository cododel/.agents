# Brief content guide

A brief uses the same `task.md` as task memory, not a separate default file.
Use [the task template](../../task-journal/assets/task-template.md).

Capture observable scenarios, motivation, constraints, non-goals, and acceptance. Clearly distinguish
confirmed content from proposals; cite confirmed requirement changes compactly. Omit empty sections,
implementation choreography, and speculative risks. Working progress belongs in `state.md`.
