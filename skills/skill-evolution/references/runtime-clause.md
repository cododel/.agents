# Runtime evolution clause

Adapt this seed into the target skill's language and domain. Replace the writable surface,
promotion scope and relevant checks with concrete known values; retain candidate-only behavior
where authority is absent. Remove authoring notes from the finished clause. Link any detailed
learning instructions from the target entrypoint, using paths inside that target package.

```markdown
## Evolution

When a direct operator correction, reproducible failure or verified workaround exposes a reusable
gap, repair the current authorized result first. Then capture the mechanism, its applicable scope,
the minimum confirming evidence and a case where the proposed rule should not apply. Your own
draft, reflection or the operator's silence does not establish a successful outcome.

Prepare a minimal change to the relevant procedure or trap, rather than a run diary. Verify the
original gap, a new relevant case and affected existing guarantees. Keep unsupported hypotheses
explicitly provisional and outside active instructions. Preserve only necessary evidence; do not
copy whole conversations, private data or secrets into the package.

Apply changes only to this skill's maintained source and only within established write and
promotion authority. Without that authority, prepare a candidate in the authorized task workspace
outside active instructions. Preferences, meaning and scope changes require operator approval
covering the rule; reuse an explicit instruction to persist that exact rule. Never infer broader
permission from a local correction. Changes to this evolution policy, trusted evidence, permissions
or approval gates require an explicit external decision.

Tell the operator what was learned, its scope, which instructions changed or remain candidates,
what checks actually ran and what remains uncertain. Preserve a recoverable exact diff or the
existing version history so the operator can reject or undo this change without losing other work.
Revise superseded guidance instead of accumulating contradictions. Recheck learning when evidence
is contradicted or relevant dependencies change; remove it only within existing authority.
```

For a utility skill with established local repair authority, name the exact maintained files and
the permitted objective repairs. For a writing skill, identify accepted source/correction pairs and
protected voice examples; a pleasing draft alone must not become a preference rule. Use existing
fixtures or evidence owners rather than creating empty ledgers or promising a future evaluator.
